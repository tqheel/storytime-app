# Version 0.0.8 Specs

## Requirements
1. Replace the UI for kiosk mode so that content is presented with Reveal.js framework
2. When a user selects a story "card", present only that card's content via Reveal.js presentation mode
3. Each story card shall contain multiple slides organized as a complete slide deck
4. Arrow navigation at the bottom of slides shall navigate only within the current card's slide deck
5. Navigation behavior requirements:
   - Right arrow advances to next slide within current card only
   - Left arrow goes to previous slide within current card only
   - Right arrow shall be disabled when user is on the last slide of current card
   - Left arrow shall be disabled when user is on the first slide of current card
   - Navigation shall not advance to content from other story cards
6. Progress indicator requirements:
   - Progress bar located at bottom of page without interfering with content view
   - Display current position as "x of y" format (e.g., "3 of 8")
   - Display percentage of completion for current card's slide deck
   - Progress bar shall update in real-time as user navigates through slides
7. Story card content structure:
   - Main story page cards shall display summary of overall content
   - Card summaries shall not be truncated views of slide deck content
   - Each card summary shall provide clear overview of what the full slide deck contains
   - Slide deck content shall be comprehensive and detailed for presentation mode
8. Integration with existing architecture:
   - Maintain compatibility with current Angular SPA structure
   - Preserve Fred Rogers visual theme and storytelling approach
   - Follow established content preservation pattern for external library integration
9. Accessibility and usability:
   - Keyboard navigation support (arrow keys, escape to exit)
   - Screen reader compatibility for progress indicators
   - Smooth transitions between slides within card context
10. Content organization:
    - Each story card maps to one complete Reveal.js presentation
    - Slides within each card shall follow logical narrative progression
    - Content shall maintain Fred Rogers' gentle, accessible teaching style
11. Markdown content rendering:
    - Create Angular service to parse Markdown content and convert to HTML
    - All current raw Markdown content in Angular components shall be dynamically rendered as HTML
    - Each story controller shall use the Markdown service to render HTML for story card slide decks
    - Service shall handle standard Markdown syntax (headers, lists, links, emphasis, code blocks)
    - Rendered HTML shall maintain security by sanitizing potentially dangerous content

## Implementation Notes
- Integrate Reveal.js library using established content preservation pattern
- Load Reveal.js scripts dynamically in ngAfterViewInit lifecycle hook
- Create slide deck data structure for each story card containing:
  - Array of slide content (HTML/markdown)
  - Card metadata (title, summary, total slide count)
  - Navigation state tracking
- Extend KioskService to support Reveal.js presentation mode
- Implement custom progress bar component that:
  - Displays outside of Reveal.js viewport
  - Updates via Reveal.js event listeners
  - Shows both numeric (x of y) and percentage progress
- Configure Reveal.js with restricted navigation:
  - Disable default keyboard shortcuts that could advance between cards
  - Implement custom navigation handlers
  - Set up slide boundaries per card
- Apply Fred Rogers theme styling to Reveal.js presentations
- Ensure compatibility with existing Angular routing and component architecture

## Technical Requirements
- Install Reveal.js npm package and update package.json dependencies
- Install Markdown parsing library (e.g., marked, markdown-it) and HTML sanitization library (e.g., DOMPurify)
- Import Reveal.js modules using ES6 imports in Angular components
- Create MarkdownService as Angular injectable service for content parsing
- Implement proper cleanup when exiting presentation mode
- Handle window resize events for responsive presentation display
- Add error handling for slide content loading and Markdown parsing
- Maintain state persistence for current slide position within cards
- Implement smooth entry/exit animations between story view and presentation mode
